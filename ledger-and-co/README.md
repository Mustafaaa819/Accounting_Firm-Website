# Ledger &amp; Co.

Marketing site for a mid-size chartered accountancy practice. Astro, Tailwind
v4, GSAP ScrollTrigger, TypeScript. It builds to plain static files in `dist/`
and deploys to Netlify, Vercel or Cloudflare Pages with no server, no runtime
and no adapter.

## Structure

```text
public/fonts/          self-hosted Fraunces + Inter (woff2, latin + latin-ext)
public/images/         og-default.png — the share card, generated, see below
scripts/               og-default.svg + the script that rasterises it
src/content/           services, team, news — Markdown, schemas in content.config.ts
src/components/        Photo, LedgerSpread, DenseTextSection, FullBleedFeature,
                       ScrollReveal, HistoryTimeline, SiteHeader, SiteFooter
src/layouts/           BaseLayout — head, meta, Open Graph, font preloads
src/pages/             one file per route, plus robots.txt.ts
src/styles/global.css  @font-face, base element styles, button classes
tailwind.config.ts     the design tokens; colours and type are replaced, not extended
```

## Before the first production deploy

1. **Set the real origin.** `site` in `astro.config.mjs` is
   `https://ledgerandco.example`. Canonical links, `og:url`, the sitemap and
   `robots.txt` are all built from it, so nothing else needs editing — but
   nothing is correct until it is changed.
2. **Activate the contact form backend** — see the section below. The form
   renders and validates without it; it just posts nowhere.
3. **Swap the placeholders.** Grep for `PLACEHOLDER`: the favicon, the share
   card, the office addresses and phone numbers in `src/data/offices.ts`, and
   the firm particulars on `/who-we-are`.

Nothing above is a code change beyond step 1, and the build fails loudly rather
than silently if `site` is missing.

## SEO and social

- **Per-page title and description** are props on `BaseLayout`; every page sets
  both. Article routes also pass `ogType="article"` and `publishedTime`.
- **`sitemap-index.xml` / `sitemap-0.xml`** are emitted by `@astrojs/sitemap` at
  build time — all 17 routes, no manual list to maintain.
- **`robots.txt`** is generated by `src/pages/robots.txt.ts` rather than dropped
  in `public/`, so its absolute `Sitemap:` line follows `site` automatically.
- **The share card** is `public/images/og-default.png`. It must stay a PNG or
  JPG: Facebook, LinkedIn and Slack do not render an SVG `og:image`. Edit
  `scripts/og-default.svg` and run `npm run og` to regenerate it, or replace the
  PNG outright with a properly designed 1200×630 card.

## Images

There is no photography yet. Every image slot renders `Photo.astro`, which
prints a flat block carrying the brief for the shoot — dimensions included — so
the layout is already the shape the real picture will be.

To ship a real one, pass `src`:

```astro
import portrait from '../assets/partners-floor.jpg';
<Photo src={portrait} label="…" alt="…" width={640} height={800} />
```

With `src` set it renders Astro's `<Image />`: hashed into `_astro/`, converted,
`srcset` generated from `image.layout: 'constrained'` in the config, and
`width`/`height` written so nothing reflows when it lands. Everything is
`loading="lazy"` by default; the homepage hero is the one `loading="eager"` call
site, because it is the only image above the fold.

Team headshots need no code change at all. Drop the file next to the Markdown in
`src/content/team/` and add `photo: ./name.jpg` — the collection schema resolves
it through `image()`, and `/` and `/who-we-are` both pick it up. A path to a file
that does not exist fails the build rather than shipping a broken portrait.

## QA

`.claude/skills/browser-qa/` drives a real headless Chromium. `qa-check.mjs`
sweeps routes at four viewports for console errors, failed requests, focus rings
and reduced-motion behaviour; `audit.mjs` measures colour contrast; and
`mobile-a11y.mjs` and `header-contrast.mjs` cover the two things the sweep
structurally cannot see (the drawer is `visibility: hidden` until opened, and
the header is translucent over whatever scrolls beneath it). Read
`.claude/skills/browser-qa/SKILL.md` before trusting any of them.

## ✉️ Contact form backend

The site is a static build, so the form on `/contact` posts to an off-box
handler. Two are wired; the choice is made at **build time** in
`src/data/contact-form.ts`, and the rendered HTML only ever carries the
attributes of the one in use.

### Default — Netlify Forms (nothing to configure)

With no environment variable set, the form is a Netlify form: `data-netlify` on
the `<form>`, a `form-name` hidden input, and a `bot-field` honeypot.
`netlify.toml` already sets the build command, publish directory and Node
version.

**Post-deploy, once:**

1. Deploy to Netlify. Netlify's post-processing scans the deployed HTML and
   registers the form automatically — but **only on a deploy of a build that
   already contains the form**, so this must be a fresh deploy, not a rollback.
2. Netlify dashboard → **Forms**. A form named `contact` should be listed. If it
   is not, the deploy that published `/contact` predates the form; redeploy.
3. **Forms → Settings → Form notifications → Add notification → Email
   notification.** Without this, submissions are collected but nobody is told.
   Point it at the firm's real mailbox.
4. Send a test enquiry from the live site and confirm it lands in both the
   dashboard and the mailbox.

Free tier is 100 submissions/month. Spam filtering is on by default (the
honeypot plus Akismet).

### Fallback — Formspree (works on any host)

Use this if the site goes to Vercel, Cloudflare Pages, GitHub Pages or plain
static hosting.

1. Sign up at [formspree.io](https://formspree.io) and create a form.
2. Copy its endpoint — the whole URL, e.g. `https://formspree.io/f/xxxxxxxx`.
3. `cp .env.example .env` and set:
   `PUBLIC_FORMSPREE_ENDPOINT=https://formspree.io/f/xxxxxxxx`
4. Set the same variable in the host's build environment, then rebuild. The
   form switches to a Formspree `action`, a `_gotcha` honeypot and a `_subject`
   line; `netlify.toml` can be deleted.
5. Confirm the recipient address on the Formspree form and send a test enquiry.
   Formspree asks you to confirm the first submission by email.

A malformed endpoint is rejected at build time with a `[contact]` warning and
falls back to Netlify, rather than building a form that posts into nothing.

### Testing it

```sh
npx astro dev --background
node .claude/skills/browser-qa/scripts/contact-form.mjs
```

Drives a real browser: validation, focus handling, the submitted request body,
and both end states. Network responses are stubbed — it proves the page's
behaviour, not the account setup, which only a live test enquiry can.
